# 座標・盤面・描画仕様

- 状態: Accepted（MVP仕様確定）

## 1. 論理座標

Canvas内部ではCSSピクセルと独立した論理座標を使う。

| 項目 | 値 |
| --- | ---: |
| Physics World幅 | 600 |
| Physics World高さ | 1500 |
| 通常表示窓 | 600 × 1000相当 |
| 左上 | `(0, 0)` |
| ターゲット中心 | `(300, 220)` |
| ストーン半径 | 18 |

座標方式は[ADR-015](../../ADR/ADR-015-separate-physics-world-and-viewport.md)に従う。`y = 0〜1000`を基本盤面、`y = 1000〜1500`を投射側バッファとする。

ターゲット中心とその奥側の盤面端は、投射距離にかかわらず固定する。得点リングの半径と境界条件は[`game-rules.md`](./game-rules.md)を正本とする。

## 2. Worldと表示窓

RendererはCameraの位置と表示倍率を使ってWorld座標を表示座標へ変換する。Pointer入力はこの逆変換によってWorld座標へ戻す。

通常時は基本盤面を表示する。投射位置を後退させる場合は、ターゲットの得点範囲と投射ストーンが同時に見える最小限の範囲へCameraを調整する。

Cameraの位置と表示倍率は、Physics、衝突、盤外判定、採点へ影響させない。画面回転やウィンドウサイズ変更でも、World座標と進行状態を変更しない。

## 3. Canvas表示

モバイル画面を基準にしつつ、PCでも利用できるようにする。通常のCanvas表示窓は縦横比`3:5`を維持し、利用可能な幅と高さの両方へ収まる最大サイズにする。

描画バッファは[ADR-029](../../ADR/ADR-029-cap-canvas-pixel-ratio-at-two.md)に従い、`min(devicePixelRatio, 2)`を反映する。`devicePixelRatio`を取得できない場合または値が不正な場合は1を使う。描画倍率はPhysicsの座標へ影響させない。

Game Screen全体の縦配置・横配置、safe-area、スクロールの扱いは[`screen-flow-and-input.md`](./screen-flow-and-input.md)を正本とする。

## 4. 投射距離と基本投射位置

ゲーム開始前にユーザーが次の3段階から1つを選択する。選択結果はそのゲームの5投中は変更しない。選択された距離に応じて投射点のy座標を変える。

| 名称 | 投射距離 | 基本投射位置 |
| --- | ---: | --- |
| SHORT | 520 | `(300, 740)` |
| MEDIUM | 620 | `(300, 840)` |
| LONG | 720 | `(300, 940)` |

投射方向は、各投射位置からターゲット中心へ向かう単位ベクトルとする。プレイヤーによる角度操作は行わない。

## 5. 投射位置の後退

最低Powerの移動距離保証`minimumTravelDistance`は[`physics.md`](./physics.md)、ストーン直径`stoneDiameter`はこの文書の「論理座標」を正本とする。

各投射前に、候補位置からターゲット方向へ`minimumTravelDistance`進むストーンの軌道が既存ストーンと重ならないか確認する。重なる場合は、基本投射位置から投射側へ`stoneDiameter`ずつ候補位置を移し、その進路を確保できる最も近い位置を使う。

初期実装では最大4段階、144 logical pxまで探索する。LONGの最大後退時は投射位置が`(300, 1084)`、ストーン下端が`y = 1102`になる。

投射位置を後退しても、選択中の投射距離名とハイスコアカテゴリーは変更しない。4段階の範囲で配置可能な位置が見つからない場合は投射を開始せず、開発時の調整対象として記録する。

## 6. ターゲットとストーンの描画

ターゲットには固定配点として、中心へ`100`、50点リング上側へ`50`、30点リング上側へ`30`、10点リング上側へ`10`を常時表示する。各数字には[`game-rules.md`](./game-rules.md)で定義した得点色トークンを適用する。数字にはSurfaceとリング色のどちらに重なっても読める高コントラストの輪郭または背景を付ける。0点領域には固定の`0`を表示しない。

ターゲットリングとストーンは、[`game-rules.md`](./game-rules.md)で定義した同じ得点色トークンを使う。盤上のストーンは現在位置から導出した暫定得点に応じて動的に色を変える。

リングやSurface背景と重なっても識別できるよう、ストーンには暗色の輪郭線を付ける。初期カラーはデザイントークンとして管理し、ICE、WOOD、FELT上で識別しにくい場合は、得点との対応を維持したままプレイテストで調整する。

## 7. Surfaceの見た目

- ICE: 明るい水色を基調とした氷風パターン
- WOOD: 茶色を基調とした木目風パターン
- FELT: 緑色を基調とした細かな布地風パターン

外部画像はMVPでは使わず、Canvas描画とCSSで表現する。
