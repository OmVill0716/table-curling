# MVPゲーム仕様

- 状態: Accepted（MVP仕様確定）

## 1. 座標と盤面

Canvas内部ではCSSピクセルと独立した論理座標を使う。

| 項目 | 値 |
| --- | ---: |
| Physics World幅 | 600 |
| Physics World高さ | 1500 |
| 通常表示窓 | 600 × 1000相当 |
| 左上 | `(0, 0)` |
| ターゲット中心 | `(300, 220)` |
| ストーン半径 | 18 |

座標方式は[ADR-015](../ADR/ADR-015-separate-physics-world-and-viewport.md)に従う。`y = 0〜1000`を基本盤面、`y = 1000〜1500`を投射側バッファとする。

モバイル画面を基準にレイアウトし、PCでも利用できるようにする。通常のCanvas表示窓は縦横比`3:5`を維持し、利用可能な幅と高さの両方へ収まる最大サイズにする。RendererはCameraの位置と表示倍率を使ってWorld座標を表示座標へ変換する。Pointer入力はこの逆変換によってWorld座標へ戻す。描画バッファは[ADR-029](../ADR/ADR-029-cap-canvas-pixel-ratio-at-two.md)に従って`min(devicePixelRatio, 2)`を反映し、Physicsの座標には影響させない。

通常時は基本盤面を表示する。投射位置を後退させる場合は、ターゲットの得点範囲と投射ストーンが同時に見える最小限の範囲へCameraを調整する。Cameraの位置と表示倍率はPhysics、衝突、盤外判定、採点へ影響させない。

### レスポンシブレイアウト

Game Screenの配置は[ADR-022](../ADR/ADR-022-use-responsive-game-layout.md)に従う。

```text
狭い画面・縦向き              横向き・幅900 CSS px以上
┌──────────────┐          ┌────────────┬────────┐
│ 情報領域       │          │            │ 情報領域 │
├──────────────┤          │   Canvas   ├────────┤
│              │          │            │ 操作領域 │
│    Canvas    │          └────────────┴────────┘
│              │
├──────────────┤
│ 操作領域       │
└──────────────┘
```

- Game Screenは動的viewportの高さへ収め、通常のページスクロールを発生させない
- safe-area insetを上下左右の余白へ加える
- 情報領域にはShot、Surface、距離を表示する
- 操作領域には投射ボタンと現在のGamePhaseで利用できる進行・リタイア操作を表示する
- 画面回転やウィンドウサイズ変更ではCanvasのCSS表示サイズと描画バッファだけを更新し、Runtime、World座標、進行状態を維持する
- Canvasの内部描画倍率は最大2とし、取得不能または不正な`devicePixelRatio`では1を使う
- 投射ボタンは長押し中のページスクロールを防ぐが、ページ全体のピンチズームは無効化しない
- Game以外の画面は内容が表示領域を超えた場合に縦スクロールできる
- Animation Frameは`charging`と`moving`で継続し、`ready`と`review`では状態・Camera・表示サイズが変わった時に1回だけ描画する

### 投射距離

ゲーム開始前にユーザーが次の3段階から1つを選択する。選択結果はそのゲームの5投中は変更しない。ターゲット中心とその奥側の盤面端は固定し、選択された距離に応じて投射点のy座標を変える。

| 名称 | 投射距離 | 基本投射位置 |
| --- | ---: | --- |
| SHORT | 520 | `(300, 740)` |
| MEDIUM | 620 | `(300, 840)` |
| LONG | 720 | `(300, 940)` |

フィールド選択でSurface、長さ選択で投射距離を選び、選択内容確認を経てゲームを開始する。Game ScreenとResult Screenには選択された距離名を表示する。

最低Powerでも、最も抵抗の大きいFELT上で投射位置から40 logical px以上進むよう`minSpeed`を調整する。これはストーン直径36 logical pxと4 logical pxの隙間に相当する。

各投射前に、候補位置からターゲット方向へ40 logical px進むストーンの軌道が既存ストーンと重ならないか確認する。重なる場合は、基本投射位置から投射側へ36 logical pxずつ候補位置を移し、40 logical pxの進路を確保できる最も近い位置を使う。初期実装では最大4段階、144 logical pxまで探索する。

LONGの最大後退時は投射位置が`(300, 1084)`、ストーン下端が`y = 1102`になる。投射位置を後退しても、選択中の投射距離名とハイスコアカテゴリーは変更しない。4段階の範囲で配置可能な位置が見つからない場合は投射を開始せず、開発時の調整対象として記録する。

## 2. 画面とゲーム進行

画面構成と状態の分離は[ADR-019](../ADR/ADR-019-separate-menu-screens-and-game-phase.md)に従う。

```text
TOP「テーブルカーリング」
├─ ゲームプレイ
│  └─ フィールド選択 → 長さ選択 → 選択内容確認 → Game → Result
├─ スコア確認
└─ 遊び方
```

TOPには「ゲームプレイ」「スコア確認」「遊び方」の3つの主要な入口と、効果音のON/OFF設定を表示する。

ゲーム設定中は「戻る」で1画面前へ戻り、既に選択した値を維持する。フィールド選択から戻るとTOP、長さ選択から戻るとフィールド選択、選択内容確認から戻ると長さ選択へ移る。選択内容確認ではフィールドと長さを表示し、「ゲーム開始」が押された後にGame Screenを開始する。

スコア確認ではフィールドごとのタブと長さのタブを表示し、選択中カテゴリーの上位3件だけを表示する。「TOPへ」でTOPへ戻る。スコア確認用のタブ選択はゲームプレイ用のフィールド・長さ選択を変更しない。

遊び方は[ADR-032](../ADR/ADR-032-use-optional-static-how-to-play-screen.md)に従い、TOPから任意に開く静的な1画面とする。ゲームの目的、Surfaceと投射距離の違い、Power Gaugeと固定投射方向、5投の進行、ストーン同士の衝突、ターゲットの固定配点、動的なストーン色、四辺のコースアウト、Resultでの最終採点、リタイア、途中保存を行わないこと、効果音設定を説明する。「TOPへ」でTOPへ戻る。初回強制表示、既読保存、チュートリアル進捗は設けず、内容がviewportへ収まらない場合は縦スクロールを許可する。

### Game Screenの進行

1. Game Screenを開始し、1投目を発射可能にする
2. 長押しでPowerをため、リリースで発射する
3. 盤面上にある全ストーンが停止するか盤外になるまでPhysicsを更新する
4. 投射結果を確認する`review`へ移る
5. 1〜4投目では「次の投射へ」が押された後に次のストーンを配置し、手順2へ戻る
6. 5投目では全ストーンを一度だけ採点してハイスコアを保存し、「結果を見る」を表示する
7. 「結果を見る」が押された後に、確定済み結果をResult Screenへ表示する

同時に運動しているストーンが1個でもある間と`review`中は、新しい投射を受け付けない。1〜4投目の`review`では、固定配点付きの盤面、ストーン、`Shot N / 5`、「次の投射へ」、「リタイア」を表示し、各ストーンの現在得点と合計得点は表示しない。5投目の`review`でも固定配点だけを表示し、各ストーンの確定得点と合計得点を伏せたまま、停止した盤面、ストーン、`Shot 5 / 5`、「結果を見る」を表示する。

### 画面状態

| `Screen` | 意味 | 主な操作 |
| --- | --- | --- |
| `top` | 入口 | ゲームプレイ、スコア確認、遊び方 |
| `fieldSelect` | フィールド選択 | ICE、WOOD、FELT、戻る |
| `lengthSelect` | 長さ選択 | SHORT、MEDIUM、LONG、戻る |
| `selectionConfirm` | 選択内容確認 | ゲーム開始、戻る |
| `game` | ゲーム | GamePhaseに従う操作、リタイア |
| `result` | 結果 | Retry、TOPへ |
| `score` | スコア確認 | フィールド・長さタブ、TOPへ |
| `howToPlay` | 遊び方 | TOPへ |

### Game Screen内の状態

| 状態 | 意味 | 許可する操作 |
| --- | --- | --- |
| `ready` | 投射待ち | 長押し開始、リタイア |
| `charging` | Powerが1〜100を往復中 | リリースして投射、キャンセル、リタイア |
| `moving` | 1個以上のストーンが運動中 | リタイア |
| `review` | 投射結果の確認中 | 1〜4投目は次の投射へ・リタイア、5投目は結果を見る |

- `リタイア`: 5投目の停止・最終結果確定より前の未完了ゲームを確認後に破棄し、Resultを表示せずTOPへ戻る
- `Retry`: Resultから同じSurface・距離で新しいゲームを始める
- `TOPへ`: Resultから確認なしで選択を解除し、TOPへ戻る

Resetは実装しない。リタイアしたゲームの得点、投数、ストーン、リタイア回数は保存しない。リタイア確認中はPower入力とPhysicsを停止する。`charging`から確認を開く場合は充電をキャンセルし、確認を取り消した場合は`ready`へ戻る。`moving`から確認を取り消した場合は、確認中の実時間をPhysicsへ加算せず`moving`を再開する。`ready`または1〜4投目の`review`から確認を取り消した場合は元の状態へ戻る。

「次の投射へ」を押した後に次の投射位置を計算し、Cameraの準備が完了してから`ready`へ移る。「結果を見る」は確定済みResultを表示するだけで、再採点やハイスコア保存を行わない。

### ページ非表示時

バックグラウンド動作は[ADR-021](../ADR/ADR-021-pause-while-page-is-hidden.md)に従う。

- Game Screenでページが非表示になった時点でPower計測とPhysicsの時間更新を停止する
- `moving`はStoneの位置と速度を維持し、再表示後に同じ状態から自動再開する
- `charging`は投射せずキャンセルし、Power表示を未操作状態へ戻して`ready`へ移る
- `ready`と`review`は状態を維持する
- 非表示中の実時間はPower、Physics accumulator、停止判定の0.25秒へ加算しない
- 再表示時に「再開」ボタンや確認画面は表示しない
- 非表示中のPointer Upとキー解放では投射しない

一時停止は途中保存ではない。再読み込み、タブを閉じる、またはブラウザによってページが破棄された場合、未完了ゲームは失われて次回は`top`から開始する。

## 3. 投射

MVPではプレイヤーによる角度操作を行わない。投射方向は、各投射位置からターゲット中心へ向かう単位ベクトルとする。

入力方式は[ADR-013](../ADR/ADR-013-use-oscillating-power-gauge.md)に従う。

Canvas外に、タッチとマウスで共通利用する円形の投射ボタンを表示する。Pointer DownまたはキーボードのSpace/EnterでPower Gaugeを開始し、Powerを1から100まで1.5秒、100から1まで1.5秒で直線的に変化させる。ボタンを押している限り、3秒周期で往復を繰り返す。Pointer Upまたはキーを離した時点で発射する。

```ts
const halfCycleSeconds = 1.5;
const phase = (heldSeconds % (halfCycleSeconds * 2)) / halfCycleSeconds;
const normalized = phase <= 1 ? phase : 2 - phase;
const power = 1 + normalized * 99;
```

Power Gaugeは円形投射ボタンの上半円を使って表示する。上半円の目盛りは、Power 1の左端を緑、中央付近を黄、Power 100の右端を赤とする固定グラデーションとし、現在のPowerに対応する位置へマーカーを表示する。ボタン内には整数の現在値と、上昇中を示す`↑`または下降中を示す`↓`を併記する。

色だけでPowerを判別させない。上半円の左右には`1`と`100`を表示し、マーカー、数値、方向矢印を常に組み合わせる。未操作時はマーカーと方向矢印を隠し、現在値を`—`と表示する。

上半円はHTMLボタンに重ねたSVGで描画できる。装飾用SVGは`pointer-events: none`とし、Pointer Eventsとキーボードイベントは下層のHTMLボタンが受け取る。SVGは投射ボタンの装飾であり、盤面をHTML Canvasで描画する[ADR-001](../ADR/ADR-001-use-html-canvas.md)の決定を変更しない。

投射ボタンではPointer Captureまたは同等の処理を使用する。`pointercancel`、ウィンドウのフォーカス喪失、または充電中のリタイア開始では投射せず、Power表示を未操作状態へ戻す。短いタップまたはクリックはPower 1の有効な投射として扱う。

操作のアクセシビリティは[ADR-031](../ADR/ADR-031-support-pointer-keyboard-and-reduced-motion.md)に従う。投射ボタンはHTML `button`を使い、アクセシブルな名前と現在Power・増減方向のHTML情報を持つ。主要操作のタップ領域は最低44 × 44 CSS pxとし、キーボードフォーカスを視認できるようにする。Power値を強制的に連続読み上げする`aria-live`は使用しない。

`prefers-reduced-motion: reduce`では装飾的な画面遷移を抑制するが、Power Gaugeの往復、ストーン、衝突、Cameraの動きはゲーム進行として維持する。

Power 1は短い距離でも必ずストーンが動く最低初速、Power 100は最大初速へ対応させる。未操作時も上半円の目盛りと`1`、`100`は表示し、Power 0は表示せず、現在値を`—`とする。

PowerからMatter.js Bodyの初速度への変換は線形とする。Power 1を`minSpeed`、Power 100を`maxSpeed`へ対応させ、同じPowerならSurfaceにかかわらず同じ初速度を与える。

```ts
const normalizedPower = (power - 1) / 99;
const speed = minSpeed + normalizedPower * (maxSpeed - minSpeed);
```

`minSpeed`と`maxSpeed`の具体値は未検証のため、プレイテストで調整する。Power 1ではFELT上でもストーンが投射位置から40 logical px以上進むこと、Power 100ではFELTかつLONGの最大後退位置からでもターゲットへ到達できることを最低条件とする。

## 4. Physics

Physics EngineにはMatter.jsを使う。詳細は[ADR-008](../ADR/ADR-008-use-matter-js.md)を参照する。距離はlogical pxとして扱い、Matter.jsの`Engine.update`を`1000 / 120`ミリ秒の固定タイムステップで呼び出す。時間制御の詳細は[ADR-002](../ADR/ADR-002-fixed-timestep-physics.md)を参照する。

### Surface

| Surface | Matter.js設定 | 特性 |
| --- | --- | --- |
| ICE | `frictionAir`低 | 低抵抗 |
| WOOD | `frictionAir`中 | 標準 |
| FELT | `frictionAir`高 | 高抵抗 |

Surfaceごとの滑りやすさは、初速度を変えずに`frictionAir`の抵抗値で表現する。衝突がない直線投射では、同じPowerに対して`ICE > WOOD > FELT`の順に停止距離が長くなるよう調整する。実際の移動距離には、抵抗に加えてストーン同士の衝突も影響する。

`frictionAir`と最終的な停止閾値は未検証のため、プレイテストで調整する。

### Physicsパラメータの調整

調整方法は[ADR-024](../ADR/ADR-024-calibrate-physics-in-storybook.md)に従う。productionアプリには調整画面やデバッグ用URLを設けず、Storybookの`Physics Calibration` Storyで調整する。

Storybook ControlsからPower、`minSpeed`、`maxSpeed`、Surfaceごとの`frictionAir`、共通`restitution`、停止速度、停止継続時間を変更できるようにする。変更時は実行中のBodyへ値を途中適用せず、選択中プリセットの同じ初期条件からRuntimeを作り直す。

Calibration StoryではCanvasに加え、現在速度、投射開始地点からの移動距離、World座標、停止理由を表示する。最低PowerのFELT直線投射、最大PowerのFELT・LONG、3 Surfaceの直線距離比較、正面衝突、停止判定を個別のプリセットとして再現できるようにする。

採用候補値はJSONとしてコピーできるが、自動保存と自動最適化は行わない。内容を確認したうえで共通Physics設定ファイルへ手動反映し、Vitestと実際のゲームプレイで再検証する。

停止判定の初期値は`Body.speed < 1.00`がPhysics上の経過時間で0.25秒継続することとする。描画フレーム数では判定しない。途中で`Body.speed >= 1.00`になった場合はそのBodyの継続時間をゼロへ戻す。

条件成立時は`Body.setVelocity(body, { x: 0, y: 0 })`と`Body.setAngularVelocity(body, 0)`を適用し、停止扱いとする。Bodyは静的化せず、後続ストーンとの衝突で速度を得た場合は継続時間をリセットして再び運動中とする。速度閾値`1.00`はプレイテスト用の初期値であり、停止が不自然に見える場合は調整する。

### ストーン同士の衝突

- 全ストーンを同じ半径・密度のMatter.js円形Bodyとする
- 衝突検出、重なり解消、速度伝達はMatter.jsへ委譲する
- 反発係数は全Surfaceで共通とし、実装開始時は`restitution: 0.85`とする
- 最終的な反発係数は、衝突時に少し速度を失いながらも100点位置のストーンを後続ストーンで弾き出せる範囲へプレイテストで調整する
- 衝突後の各ストーンには、選択中Surfaceの`frictionAir`が引き続き作用する
- 固定タイムステップを使い、調整後の最大初速度における正面衝突ですり抜けないことを確認する

### 盤外

境界の方式は[ADR-014](../ADR/ADR-014-use-out-of-bounds-on-all-edges.md)に従う。

- 盤面の四辺にMatter.jsの静的な反射壁を作成しない
- ストーン全体が左端、右端、上端、Physics World下端のいずれかを越えた時点、すなわち中心が`x < -18`、`x > 618`、`y < -18`、`y > 1518`のいずれかを満たした時点で盤外とする
- 盤外ストーンは描画、摩擦、衝突判定から除外するが、Result用データには0点として残す

## 5. 採点

採点方式と表示タイミングは[ADR-023](../ADR/ADR-023-show-colored-score-labels-on-target.md)に従う。

5投目に関係する全ストーンの運動が終了した時点で一度だけ採点する。各ストーンの中心とターゲット中心の距離`d`を使う。ストーン半径は得点判定に含めない。

| 条件 | 得点 | 色トークン | 初期カラー |
| --- | ---: | --- | --- |
| `0 <= d && d <= 30` | 100 | `score.100` | 赤 `#D32F2F` |
| `30 < d && d <= 60` | 50 | `score.50` | オレンジ `#F57C00` |
| `60 < d && d <= 90` | 30 | `score.30` | 黄 `#FBC02D` |
| `90 < d && d <= 120` | 10 | `score.10` | 青 `#1976D2` |
| `120 < d`または盤外 | 0 | `score.0` | グレー `#757575` |

境界線上は内側の高い得点に含める。ターゲットリングとストーンは同じ得点色トークンを使う。盤上のストーンは現在の中心位置から暫定得点を毎フレーム導出し、対応する色へ動的に変える。リングやSurface背景と重なっても識別できるよう、ストーンには暗色の輪郭線を付ける。

ターゲットには固定配点として、中心へ赤い`100`、50点リング上側へオレンジの`50`、30点リング上側へ黄色の`30`、10点リング上側へ青い`10`を常時表示する。数字にはSurfaceとリング色のどちらに重なっても読める高コントラストの輪郭または背景を付ける。0点領域には固定の`0`を表示しない。

Game Screenでは固定配点以外に、各ストーンの現在得点、暫定合計、得点変化ポップアップを表示しない。プレイ中はストーン色だけを現在位置に応じて変え、ストーン上には得点数値を表示しない。暫定得点と色は確定得点として保存しない。

5投目に関係する全ストーンの運動が終了した時点で、5個のストーンを一度だけ採点する。合計の最大は500点とする。確定結果は同投目の`review`では非表示とし、「結果を見る」の押下後、Resultで各ストーンの確定得点と合計得点をHTMLテキストとして初めて表示する。初期カラーはデザイントークンとして管理し、ICE、WOOD、FELT上で識別しにくい場合は意味の対応を維持したままプレイテストで調整する。

### Result Screen

- Final Scoreとして合計得点を画面内で最も大きく表示する
- Shot 1〜5を投射順に並べる
- 盤内ストーンは最終色と得点数値を表示する
- 盤外ストーンは色を得点表示に使わず、`OUT`と`0`を表示する
- 選択したSurfaceと投射距離を表示する
- 今回の記録が該当カテゴリーの上位3件へ入った場合は、`NEW HIGH SCORE`と`1st`、`2nd`、`3rd`のいずれかを表示する
- ハイスコア圏外の場合は`NEW HIGH SCORE`と順位を表示しない
- 座標値と途中得点は表示しない
- `Retry`は同じSurface・距離で新しいゲームを始める
- `TOPへ`は確認なしで選択を解除してTOPへ戻る

同点順位はハイスコアの並び順と同じく`achievedAt`の降順とし、新しい記録を上位にする。

## 6. Surfaceの見た目

- ICE: 明るい水色を基調とした氷風パターン
- WOOD: 茶色を基調とした木目風パターン
- FELT: 緑色を基調とした細かな布地風パターン

外部画像はMVPでは使わず、Canvas描画とCSSで表現する。

## 7. ハイスコア

保存方式は[ADR-010](../ADR/ADR-010-store-category-high-scores-locally.md)に従う。

Surface 3種類と投射距離3種類を組み合わせた9カテゴリーごとに、上位3件を保存する。

保存先は`localStorage`、保存キーは`table-curling.high-scores.v1`とする。

```ts
type HighScoreRecord = {
  score: number;
  achievedAt: string; // ISO 8601
};
```

スコア確認画面ではSurfaceを大カテゴリー、投射距離を切り替え項目として、選択中カテゴリーの上位3件を表示する。得点の降順、同点なら`achievedAt`の降順とする。

ハイスコアは5投目に関係する全ストーンが停止または盤外になり、最終得点が確定した時点で一度だけ更新する。「結果を見る」の押下有無は保存結果に影響しない。

ゲーム途中のSurface、投射距離、投数、ストーン、Power、`Screen`、`GamePhase`、Camera、暫定得点は永続化しない。途中でタブを閉じるか再読み込みした場合、そのゲームと画面位置は破棄され、次回は`top`から開始する。途中再開と復元確認は提供しない。永続化するゲーム関連データはハイスコアだけとし、ユーザー設定として効果音のON/OFFを別キーへ保存する。

## 8. 音声

音声方針は[ADR-020](../ADR/ADR-020-add-sound-effects-with-user-setting.md)、素材選定は[ADR-025](../ADR/ADR-025-bundle-selected-kenney-sound-effects.md)、衝突音の多重再生制御は[ADR-026](../ADR/ADR-026-limit-stone-collision-bell-playback.md)、読み込みは[ADR-027](../ADR/ADR-027-preload-audio-without-blocking-gameplay.md)に従う。

- 投射、ストーン同士の衝突、全ストーンの停止、コースアウトに効果音を付ける
- BGMと端末の振動は実装しない
- TOPで効果音をON/OFFでき、初期値はONとする
- ユーザー操作前には再生せず、音声を再生できない場合もゲームを継続する
- OFFへ切り替えた時点で再生中の音を停止し、以後の再生を開始しない
- 設定は`table-curling.sound-enabled.v1`へBooleanとして保存する
- 素材は自作、Public Domain、または利用条件を確認したものだけを使う
- 投射は`/audio/shot.ogg`（配布元`phaseJump1.ogg`）、ストーン衝突は`/audio/stone-collision.ogg`（配布元`impactBell_heavy_001.ogg`）、全ストーン停止は`/audio/all-stones-stopped.ogg`（配布元`footstep_carpet_000.ogg`）、コースアウトは`/audio/out-of-bounds.ogg`（配布元`zapThreeToneDown.ogg`）を使う
- 選定素材はOgg Vorbisのままアプリへ同梱し、古いブラウザ向けの別形式はMVPでは用意しない
- 衝突音は衝突開始時だけを候補とし、ごく弱い接触を除外する
- 同一Physicsステップでは最も相対速度が大きい衝突だけを鳴らし、再生後250msは次の衝突音を鳴らさない
- 衝突音の初期音量は35%とし、弱い接触の閾値を含む数値は実装後にStorybookで試聴して調整する
- TOP表示後に4音源をバックグラウンドで事前読み込みし、最初のユーザー操作時に音声機能の有効化を試みる
- 音声が未準備または再生不能でもゲームを待たせず、そのイベントの音を後から再生しない

効果音は操作や状態の唯一の通知手段にしない。投射、停止、コースアウトは画面上でも判別できる状態を維持する。
