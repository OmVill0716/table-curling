# ADR-019: メニュー画面を分割しScreenとGamePhaseを分離する

- 状態: Accepted
- 決定日: 2026-08-23
- 置換対象: [ADR-017](./ADR-017-use-top-and-retire-flow.md)

## コンテキスト

ADR-017ではTOPにタイトル、Surface・距離選択、ハイスコア、Game開始を集約していた。しかし、モバイル中心の画面へ選択と情報を集めると、入口の役割が増え、操作順も分かりにくくなる。ゲーム設定、スコア閲覧、遊び方を独立した画面へ分ける必要がある。

また、従来の`GamePhase`はTOPやResultなどの画面と、`ready`や`moving`などGame Screen内の状態を同じUnionで管理していた。画面遷移とPhysics進行は責務が異なる。

## 決定

- React Routerは導入せず、公開URLはアプリのルートだけとする
- TOPにはタイトル「テーブルカーリング」と「ゲームプレイ」「スコア確認」「遊び方」の3つの入口だけを表示する
- ゲームプレイは「フィールド選択 → 長さ選択 → 選択内容確認 → Game → Result」の順に進める
- 選択内容確認ではフィールドと長さを表示し、「ゲーム開始」と「戻る」を提供する
- 設定中の「戻る」は1画面前へ戻り、既に選んだ値を維持する
- スコア確認はフィールドごとのタブと長さのタブを持ち、選択カテゴリーの上位3件だけを表示する
- 遊び方はゲームの目的、Power操作、5投の進行、動的なストーン色、コースアウト、Resultでの最終採点を説明する
- 画面は`Screen`、Game Screen内の状態は`GamePhase`として別々に管理する
- `Screen`は`top`、`fieldSelect`、`lengthSelect`、`selectionConfirm`、`game`、`result`、`score`、`howToPlay`を持つ
- `GamePhase`は`ready`、`charging`、`moving`、`review`だけを持つ
- ゲーム開始後の通常の「戻る」は設けず、最終結果確定前に終了する場合は従来の判断を引き継ぐ「リタイア」を使う
- Resultの「Retry」は同じフィールド・長さで新しいGameを開始し、「TOPへ」は選択を解除してTOPへ戻る
- ブラウザの戻る・進む操作には画面遷移を連動させない

## 影響

- TOPの情報量を抑え、目的別に画面を移動できる
- ゲーム設定を順番に選べるため、選択内容を確認してから開始できる
- スコア確認とゲーム設定の選択状態を混同せずに管理する必要がある
- 従来の`GameStore.phase`を`screen`と`gamePhase`へ置き換える必要がある
- StorybookとE2Eで各画面と戻る操作を個別に検証する必要がある
- ADR-010など過去ADR内のStage Select表記は、現行仕様ではフィールド選択・長さ選択・選択内容確認の一連の画面として読み替える
