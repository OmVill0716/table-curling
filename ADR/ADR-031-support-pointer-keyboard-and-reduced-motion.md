# ADR-031: Pointerとキーボード操作を提供し装飾的な動きを抑制する

- 状態: Accepted
- 決定日: 2026-08-23

## コンテキスト

本ゲームはモバイルを主対象としつつPCにも対応するため、投射操作をタッチ専用またはマウス専用にできない。また、色付きPower GaugeとCanvas上の動きだけでは、キーボード利用者や読み上げ環境で操作状態を把握しにくい。

ストーンの運動とPowerの往復はゲームルールそのものであり、一般的な画面遷移アニメーションと同じように停止するとゲーム性が変わる。一方、装飾だけを目的としたアニメーションは、利用者の動きを減らす設定へ従うことができる。

## 決定

- タップとマウス操作は同じPointer Eventsで扱う
- 投射ボタンはネイティブのHTML `button`を基礎とし、SpaceとEnterの長押し・解放でもPointer操作と同じPower決定を行えるようにする
- Pointer、キーボード、プログラムによるフォーカスの状態を扱い、キーボード操作時に視認できるフォーカス表示を消さない
- 投射、次の投射、結果を見る、リタイア、Retry、TOPへ戻るなど主要操作のタップ領域を最低44 × 44 CSS pxとする
- 投射ボタンには用途を示すアクセシブルな名前を付け、現在のPower数値と増減方向をHTMLとして関連付ける
- Powerの変化を強制的な`aria-live`連続通知にはせず、利用者が現在値を参照できる情報として提供する
- 色だけに依存せず、Powerは数値と方向、ターゲットは固定配点、Resultは得点テキストを併用する
- `prefers-reduced-motion: reduce`では画面遷移、フェード、装飾的な拡大縮小など、ゲームルールに関係しないアニメーションを停止または即時完了させる
- `prefers-reduced-motion`の設定にかかわらず、Power Gaugeの往復、ストーンの運動、衝突、Camera表示はゲーム進行に必要なため維持する
- ページ全体のピンチズームを無効化しない既存方針を維持する

## 影響

- タッチ、マウス、キーボードで同じ5投の流れを完了できる
- 入力方式ごとに別のゲームロジックを持たず、投射開始・確定・キャンセル処理を共有する必要がある
- 現在Powerを毎フレーム読み上げて操作を妨げることを避けつつ、HTML上では状態を取得可能にできる
- MUIやCSSの装飾的なtransitionを追加する場合、`prefers-reduced-motion`時の無効化も実装する必要がある
- Physics運動は軽減対象外のため、遊び方画面でストーンが動くゲームであることを説明する
