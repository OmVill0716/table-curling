# ADR-017: TOPを入口とし未完了ゲームにリタイアを設ける

- 状態: Superseded
- 決定日: 2026-08-23
- 置換対象: [ADR-009](./ADR-009-use-state-based-screen-flow.md)
- 置換先: [ADR-019](./ADR-019-separate-menu-screens-and-game-phase.md)

## コンテキスト

ADR-009ではStage Select、Game、Resultを状態で切り替えることにした。その後、入口画面がSurface・距離選択だけでなく、タイトルとハイスコアも扱うことが確定したため、Stage SelectよりTOPのほうが役割を正確に表す。また、プレイ途中で終了したい場合に、ゲームを初期化して同じ条件で続けるResetではなく、未完了ゲームを明示的に放棄する操作が必要になった。

## 決定

- React Routerは導入せず、公開URLはアプリのルートだけとする
- Zustandの`phase`を正本としてTOP、Game、Resultを切り替える
- 入口状態の名前は`top`とし、タイトル、Surface・距離選択、カテゴリー別ハイスコア、Game開始を提供する
- Resetは実装しない
- 5投目の停止・最終結果確定より前の未完了Gameでは「リタイア」を表示する
- リタイアは確認後にゲーム途中の状態を破棄し、Resultを表示せずTOPへ戻る
- リタイアしたゲームの得点、投数、ストーン、リタイア回数は保存しない
- 5投目停止後の`review`ではゲーム完了済みとしてリタイアを表示せず、ADR-016の「結果を見る」を表示する
- Resultでは、同じSurface・距離で新しいゲームを始める「Retry」と、確認なしで選択を解除して戻る「TOPへ」を表示する
- ブラウザの戻る・進む操作にはゲーム内画面遷移を連動させない

## 影響

- TOPがゲームの唯一の入口になる
- プレイヤーは未完了ゲームを明示的に放棄できる
- 同じ条件で途中からやり直すResetはできない
- `GamePhase`の`stageSelect`は`top`へ置き換わる
- リタイア確認中は入力とPhysicsを安全に停止し、キャンセル時の復帰を扱う必要がある
- ADR-010など過去ADR内のStage Select表記は、現行仕様ではTOPとして読み替える
