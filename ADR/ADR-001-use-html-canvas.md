# ADR-001: 盤面描画にHTML Canvasを使う

- 状態: Accepted
- 決定日: 2026-08-23

## コンテキスト

IssueではHTML Canvasを第一候補、SVGを代替候補としていた。盤面は毎フレーム複数のストーン、ターゲット、Surfaceパターンを再描画する。Reactの再レンダリングと高頻度描画を分離する必要がある。

## 決定

簡易なゲームを扱いやすく実装することを優先し、MVPの盤面描画にはHTML Canvas 2D Contextを使う。MUIは画面、ボタン、ゲージ、スコアなどのUIにのみ使う。

Canvasは600 × 1000の論理座標を持ち、CSS表示サイズと`devicePixelRatio`を描画時に変換する。RendererはPhysics Runtimeの読み取り専用スナップショットを受け取り、状態変更を行わない。

## 検討した選択肢

SVGは各ストーンをDOM要素として扱え、要素単位のイベントやアクセシビリティを実装しやすい。一方、今回の盤面は少数の円をゲームループで継続描画するだけであり、SVGの要素管理を利用する利点が小さいため採用しない。

## 影響

- 毎フレームの座標をReact stateへ保存せずに描画できる
- Surfaceの色やパターンを外部画像なしで表現できる
- Canvas内部要素はDOMとしてアクセシブルではないため、操作と結果はMUI側にも提供する必要がある
- Canvas内部のオブジェクトごとのイベントや当たり判定が必要になった場合は、座標から自前で判定する必要がある
- 表示サイズから論理座標への入力変換と、高DPI対応が必要になる
- DOM要素として個別に検査できないため、描画処理と状態を分離してテスト可能にする必要がある
